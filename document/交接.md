### ✨ 新增功能与特性 (Features)
- **Windows 平台抽象层 (`src/platform/`)**：
  - `src/platform/fs.ts`：提供 `isWindows`、`isOwnedByCurrentUser`、`isRegularUserFile`、`isUserDirectory`，消除 Windows 下 `stat.uid === 0` 与 `process.getuid === undefined` 的误报。
  - `src/platform/paths.ts`：统一映射 Windows/macOS 默认路径（`%LocalAppData%\Programs\Antigravity`、`%AppData%\Antigravity`、`%LocalAppData%\GravityBox`），支持 Named Pipe 端点哈希生成（`\\.\pipe\gravitybox-<sha256>`）及同时兼容 `app.asar` 与解包 `resources\app\package.json` 的探测布局。
  - `src/platform/process.ts`：统一进程列表、回环监听端口查询及大小写不敏感路径匹配。
  - `src/platform/win-helper.ts`：封装 `gb-win-helper.exe` 调用（含低完整性环境回退机制）。
- **零外部依赖 Win32 原生辅助程序 (`native-win/gb-win-helper/`)**：
  - 使用纯 Rust Win32 FFI 编译生成 `gb-win-helper.exe`，提供 `cred read/write/delete`（Windows Credential Manager，密码走 `stdin` 防暴露）、`tcp-owners`、`ls-ports`、`ps-list`（`K32EnumProcesses` + `NtQueryInformationProcess`）、`exe-info`（PE 版本 + `WinVerifyTrust`）及 `trash`（动态加载 `shell32.dll` `SHFileOperationW`）。
- **跨平台凭据与数据库事务适配**：
  - `src/account-keychain.ts` / `src/accounts.ts`：实测确认 Windows 版 Antigravity 在凭据管理器 `gemini:antigravity` 中直接存储原生 UTF-8 JSON（区别于 macOS 的 `go-keyring-base64:`），新增 `decodeKeyringPayload` 双格式解析，并在 Windows 上以原生 JSON 写入。
  - `src/account-switch.ts`：`DatabaseTransaction` 由 `/usr/bin/sqlite3` 子进程迁移为 Node 内置 `node:sqlite` (`DatabaseSync`) 事务实现。
- **Windows 专项测试 (`test/platform-windows.test.mjs`)**：覆盖路径/命名管道隔离、文件属主校验、双格式 keyring 解析、WinCred 读写删闭环、PE 版本与进程列表校验。

### 🐞 修复的问题与缺陷 (Bug Fixes)
- **SQLite 读句柄未关闭导致 Windows `EBUSY`**：`src/sqlite-worker.ts` 中 `openSession` / `closeSession` 原写法在无活动事务时 `ROLLBACK;` 抛异常跳过 `database?.close()`，现已拆分为独立 `try/catch` 保证关闭句柄。
- **测试夹具 FIFO 清理顺序导致 Windows `EPERM`**：修复 `test/final-release-audit-111.test.mjs`、`test/hud-audit-remediation-111.test.mjs`、`test/hud-oversized-step.test.mjs` 中 `t.after(rmSync)` 注册在 `t.after(db.close)` 之前的顺序问题。
- **Node 信号终止在 Windows 下导致测试挂起**：`test/controller-contracts.test.mjs` 与 `test/tasks-contracts.test.mjs` 的 `stop(child)` 增加 `child.signalCode !== null` 判定，避免 Windows 无法捕获 `SIGTERM` 时死等二次 `SIGKILL` 的 `exit` 事件。
- **低完整性驱动器 (`F:\`) 兼容**：`F:\` 目录继承 `Low Mandatory Level` 会拦截静态 `shell32.dll`（`0xC0000142`）及限制低完整性进程读取中完整性进程信息；已改为动态加载 `shell32.dll` 并在 `winPsList` / `winTrashMove` 中自动回退 PowerShell 中完整性执行路径（在正常 `%LocalAppData%` 部署环境下直走原生 Win32 helper）。
